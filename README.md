# 디딤돌 (행정업무 효율화)

2026 공공 AI 대전환 챌린지 세션1(자유주제) 출품작.

사업지구 관련 문서(PDF·한글·워드·엑셀·텍스트)를 폴더째 넣으면 항목별 최신값을 출처와 함께 DB로 만듭니다. 문서끼리 값이 충돌하면 담당자에게 선택을 요청하고, 확정된 값으로 목적별 자료표와 보고서 초안을 만듭니다.

- 접속 주소: 실행 후 브라우저에서 http://localhost:8501
- 모의데이터: 가상 지구 '누리마루지구' 합성 문서 (실제 사업·기관·문서와 무관, 개인정보 없음)
  - `sample/` 기본 문서 11개: 사업비·연장·시기 등 수치 (정답표 기준)
  - `sample/extra/` 현안 문서 7개: 가온시 노선 반대 회신, 노선별 현안 점검회의, 다온시 협의결과, 가온시 TF 대안노선 조건부 합의, 현안 보고 초안, 교육청 협의 메모(비공식), 노선별 현안 관리대장. 사업별 **추진상태·현안·향후계획**(문장형 항목)이 들어 있음. 샘플 모드에서 "현안 문서 7개 포함"으로 켜고 끔(기존 11개 항목 판정 결과는 바뀌지 않음)
  - `sample/other/` 다른 가상 지구 문서 8개: **한빛지구**(한빛IC 연결도로·새솔로 확장·한빛선 연장·한빛 BRT·한빛 환승주차장), **솔내지구**(솔내 연결도로·솔내역 환승센터·솔내 순환버스 지원). 주민 반대, 지자체 사업비 증액 요구, 예타 재조사, 지자체 직접 시행 등. 통합 비교·질문하기용(누리마루 판정 결과는 바뀌지 않음)
  - 현안·다른 지구 문서와 그 추출 예시(`candidates_extra.csv`, `candidates_other.csv`)는 `tools/make_extra_samples.py`로 다시 만들 수 있음(개발용, `pip install fpdf2` 필요)

## 웹 데모 (설치 없이 바로 보기)
- **https://jinho517-stack.github.io/didimdol/** — 브라우저 안에서 앱이 돌아갑니다(stlite: Streamlit 브라우저판). 처음 열 때 30초~1분 걸립니다.
- 샘플 모드만 됩니다(API 키·실제 문서 추출 없음). 작업 내용(선택·DB)은 각자 브라우저 안에만 남고, 새로고침하면 처음 상태로 돌아갑니다.
- "📂 문서 → 추출 시작"부터 눌러 보세요.

## 주요 기능

| 화면 | 기능 |
|---|---|
| 📂 문서 | 폴더 경로 또는 여러 파일 선택 → "추출 시작". 등록된 문서마다 지구·단계(확정·승인본/협의결과/보고/초안/비공식)·일자·버전을 고치면 전체를 다시 판정하고 바뀐 항목을 보여 줌 |
| 🔎 통합 비교 | 여러 사업지구의 사업을 한 표로: 지구·사업 유형(도로/철도/환승/대중교통)·사업비 범위·시행주체 구분(지자체 기초/광역, LH, 국가·공공기관)·현안 낱말로 필터. 사업비 비교 차트, 현안 모아 보기, CSV |
| 💬 질문하기 | 질문을 검색 조건으로 바꿔 DB를 바로 조회(예: "지자체에서 1천억 미만의 유사 도로사업을 검토하라는데 다른 사업지구에 사례가 있을까?" → 현재 지구 제외·도로·1,000억원 미만). 검색 조건과 결과 표를 함께 표시. 키가 없으면 규칙으로, 있으면 AI가 조건을 해석하고 답을 씀(숫자는 DB 값만) |
| 📊 대시보드 | 사업지구 선택 / 요약 카드(문서·항목·확정·확인 필요·비공식 참고) / **확인 필요**: 규칙으로 못 정한 충돌 후보를 나란히 보고 버튼으로 확정(선택 기록 저장) / **사업별 최신값 카드**: 값, 판정 유형, 근거 문서, 처음 값에서 바뀐 경우 표시, 비공식 메모는 "반영 안 함"으로 표시 / **문서 흐름** 차트 / **항목 이력**: 문서별 값 변화 차트와 변경 이력 / 전체 표·CSV |
| 📝 보고서·자료 | 보고서 초안 자동 작성(공공기관 개조식: 제목 상자 → □ 대제목 → ㅇ (핵심어) → - 세부 → ⇒ 대응방안 → 주)). **양식**(추진현황 보고 / 현안사항 보고 / 총괄 현황표 / 직접 구성)을 고르면 목차가 미리 체크되고, 목차(개요·사업개요·추진경위·추진현황·주요 변경사항·주요 현안·향후 계획·참고·종합 의견)를 켜고 끄면 체크한 목차만으로 작성. 주요 현안·향후 계획은 직접 입력 줄을 덧붙일 수 있음. 대상 사업 선택. **한글(hwpx)**·워드(docx)·자료표 엑셀(값마다 출처) 내려받기 |

- **A01 추출**: 문서 텍스트에서 항목 후보를 LLM으로 뽑습니다(문서에 없는 값은 만들지 않음, 값마다 위치).
- **사업지구**: 문서마다 지구가 있고(파일명에 지구 이름이 있으면 자동, 화면에서 수정), 판정은 지구별로 따로 합니다. 지구·사업·항목은 `config.yaml`의 `districts`(지구별 사업과 유형)와 `item_templates`(유형별 항목)로 정합니다.
- **A02 판정**: LLM 없이 규칙(`resolver.py`)만으로 정합니다. 문서 단계 > 같은 단계면 최근 일자 > 같은 일자면 최종·변경안·원안 순. 모두 같은데 값이 다르면 사람에게 묻습니다. 비공식 메모는 값을 바꾸지 않고 '참고'로만 표시합니다. 같은 입력이면 문서 순서와 관계없이 항상 같은 결과입니다.
- **샘플 모드**: API 키가 없으면 `sample/candidates_sample.csv`(A01 추출 결과 예시)로 A02 이후 전체 흐름을 실행합니다.
- **모델 교체**: `config.yaml`만 바꾸면 됩니다(아래).
- 원본 문서는 읽기만 하고, DB·자료표·초안·업로드 사본은 `output/` 폴더에만 만듭니다.

## 실행 방법

Python 3.10 이상이 필요합니다.

### Windows (PowerShell)
```powershell
cd didimdol
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python selftest.py
streamlit run app.py
```

### macOS / Linux
```bash
cd didimdol
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python selftest.py
streamlit run app.py
```

`python selftest.py`는 화면 없이 인수 시험을 돌립니다(판정 규칙 시험, 정답표 11개 항목 일치, 충돌 선택, 비공식 메모, 문서 11개 읽기 등). "모든 시험 통과"가 나오면 정상입니다.

### 시연 순서 (키 없이)
1. 📂 문서 → 샘플 모드(현안 문서·다른 지구 문서 포함) → "추출 시작" (자동으로 대시보드로 이동)
2. 📊 대시보드 → "확인 필요" 카드에서 누리마루선(광역철도) 개통목표 `2031.12(으)로 확정`
3. 📊 대시보드 → 환승센터 카드: 규모 12,000㎡ 확정, 비공식 메모 8,000㎡는 "반영 안 함". 아래 "항목 이력 보기"에서 다온방면 도로확장 / 연장(0.6 → 0.8km) 선택
4. 📝 보고서·자료 → 양식 "현안사항 보고" → 목차 확인(사업개요·추진경위·주요 현안·향후 계획) → "보고서 초안 만들기" → 한글(hwpx)·워드·엑셀 내려받기
5. 🔎 통합 비교 → 사업 유형 "도로", 사업비 범위 0~1,000억 → 3개 지구의 도로사업 비교
6. 💬 질문하기 → 예시 질문 "지자체에서 1천억 미만의 유사 도로사업들을 … 다른 사업지구에 이런 사례가 있을까?" → 검색 조건과 결과 확인

### 실제 추출(LLM) 사용
키 값은 파일에 쓰지 않고 환경변수로만 넣습니다.
```powershell
$env:ANTHROPIC_API_KEY = "<키>"
streamlit run app.py
```
키가 있으면 ① 화면에 "실제 추출 (LLM)"이 나타납니다. 폴더 경로 기본값은 `sample/`입니다.

## 모델 교체 (`config.yaml`)
앱의 모든 LLM 호출은 `llm.py`의 `ask(prompt, system=None, json_mode=False)` 한 곳을 거칩니다.

```yaml
llm:
  provider: openai_compatible      # anthropic 또는 openai_compatible
  model: <모델 이름>
  base_url: http://localhost:11434/v1
  api_key_env: OPENAI_API_KEY      # 키가 필요 없는 로컬 서버면 ""
```
LLM에는 항상 JSON 출력을 요구하고, 파싱에 실패하면 한 번 재시도합니다.

## 파일 구성
```
app.py         화면 (Streamlit)
llm.py         LLM 호출 (모델 교체 지점)
config.yaml    provider, model, base_url, api_key_env, 사업지구·사업(유형)·유형별 항목
catalog.py     지구·사업·항목 목록, 사업 유형·시행주체 구분
extract.py     A01: 문서 읽기(pdf/docx/xlsx/hwpx/txt) + LLM 항목 후보 추출
resolver.py    A02: 판정 규칙 (기준 구현 a02_resolver/resolver.py 원본 그대로)
test_resolver.py  A02 기준 시험 (원본 그대로, sample 폴더에서 실행)
db.py          SQLite (facts, history, sources, choices, candidates)
query.py       A03: 목적별 자료표 + 엑셀
compare.py     여러 지구 통합 비교·검색, 질문 → 검색 조건(규칙/AI)
draft.py       A04: 보고서 초안 (화면 미리보기, 한글 hwpx, 워드 docx)
templates/     보고서 한글 서식 (모의 문서 기반 합성 서식)
selftest.py    인수 시험
sample/        모의 문서 11개 + candidates_sample.csv
output/        산출물 (원본과 분리)
```

## 알려진 제약사항
- 문서 단계는 파일명으로 추정하며, 업로드 화면에서 사람이 확인·수정합니다.
- 단위가 다른 값(예: 억원과 백만원)의 정규화는 하지 않습니다. 추출 항목 목록의 단위로 통일하도록 LLM에 요구합니다.
- 도면 인식(OCR), 로그인·권한은 범위 밖입니다. 여러 사업지구 통합 비교·질문하기는 요구사항상 범위 밖(Out)이던 기능을 확장으로 덧붙인 것이며, 핵심 흐름(A01~A04)과 정답표 판정에는 영향이 없습니다.
- 질문하기의 규칙 해석은 유형·금액(억/천억/조, 미만·이하·이상·초과)·시행주체·지구 이름·현안 낱말을 알아봅니다. 그 밖의 표현은 API 키를 넣어 AI 해석을 쓰세요(검색과 숫자는 항상 DB에서). 스캔 PDF(텍스트 없는 이미지)는 읽지 못합니다.
- 한글(hwpx) 보고서는 서식 파일의 문단 모양을 복제해 만들며, 표는 한글본에서는 사업별 ㅇ 항목으로 대신합니다(워드본에는 표 포함).
- 문장형 항목(추진상태·현안·향후계획)도 수치와 같은 규칙(단계 > 최근 일자 > 버전)으로 정합니다. 문장이 조금만 달라도 다른 값으로 보므로, 같은 단계·같은 날짜 문서끼리 표현이 다르면 '확인 필요'가 됩니다.
- 사용 오픈소스 라이선스: fpdf2(LGPL-3.0, 샘플 PDF 생성 도구에서만 사용·앱 실행에는 불필요), Altair(BSD-3-Clause, Streamlit에 포함), Streamlit(Apache-2.0), pandas(BSD-3-Clause), openpyxl(MIT), python-docx(MIT), pdfplumber(MIT), PyYAML(MIT). 제출 전 각 저장소에서 최종 확인하세요.
